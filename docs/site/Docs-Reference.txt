01
Programs and modules

Executable

A program is a sequence of top-level declarations. Mark a declaration 
export
 to publish it, and 
import { ... } from "file.mh"
 to bring named declarations in from another file, optionally under a local alias. 
import
 is the only cross-file mechanism.

TWO-FILE EXAMPLE

shared.mh

export agent Echo {
    command: "echo"
    args: ["${prompt}"]
}

export prompt Greeting(name: string) {
    "Hello, ${name}!"
}

main.mh

import {Echo, Greeting as Hello}
    from "shared.mh"

pipeline Welcome {
    input name: string
    step Run {
        log(Echo.run(
            prompt: Hello(name: name)
        ))
    }
}

Form

Syntax

When to use it

Export

export prompt Name(...) { ... }

Make a declaration reusable.

Import names

import {A, B} from "file.mh"

Bring in explicit contracts only.

Local alias

import {LongName as Short} from "file.mh"

Avoid collisions and improve readability.

NOTE

import
 merges the target file's declarations into the program's flat namespace (transitively — an imported file's own 
import
s come along), so a name resolves the same however it arrived. There is no namespace-qualified import.

NUMBERS & DURATIONS

A number is digits with an optional single decimal point (
3
, 
0.2
) — it carries no type suffix. A duration is an 
integer
 followed by a unit: 
ms
, 
s
, 
m
,

,

,

,

) is a parse error, not a number followed by a name. A string literal is always a string — even when its content is exactly an operator, so

 is a literal form, 
not
 a declarable type: it is accepted only where an operation or a config field expects one (

,

,

TYPE ALIASES

type Name = <type>
 names a type expression so a repeated or verbose shape is written once. An alias is only a spelling — it resolves to exactly the type its target denotes, adds no distinct type, and is usable anywhere a 
: type
 annotation is (inputs, parameters, returns, shape fields). Aliases may reference other aliases. A cycle, a duplicate name, an unknown target, or a name that shadows a builtin keyword is a static error (
mhl lint
).

type Slug      = string
type Ids       = string[]
type Violation = { code: string, severity: string }

tool Report {
    add(slug: Slug, issues: Violation[]): Ids -> issues.map((v) -> v.code)
}

ENUMS

enum Name { A, B, C }
 declares a closed set of named constants. A value is produced only by qualified access — 
Name.A
 — and at run time it is a distinct tagged value, not a string: 
Status.Draft == "Draft"
 is 
false
, 
type_of(Status.Draft)
 is 
"enum"
, and 
"${Status.Draft}"
 / 
json.stringify
 render the bare variant (
Draft
). 
: Name
 is a type annotation like any other. A 
match
 over an enum value is checked for exhaustiveness by 
mhl lint
.

enum Status { Draft, Published, Archived }

pipeline Publish {
    input status: Status
    step Decide {
        var note = match status {
            Status.Draft     -> "hold"
            Status.Published  -> "ship"
            Status.Archived   -> "skip"
        }
        log(note)
    }
}

PRACTICAL GRAMMAR

declaration  := [export] (import | agent | prompt | memory | tool | extension | pipeline | workflow | type | enum | test)
import       := "import" "{" name ["as" alias] {"," name ["as" alias]} "}" "from" string
extension    := "extension" kind identifier "{" {property} "}"   // kind is "mcp", "a2a" (built in), or an installed adapter's kind
type-alias   := "type" identifier "=" type
enum         := "enum" identifier "{" [identifier {"," identifier}] "}"
variable     := "var" identifier "=" expression
constant     := "const" identifier "=" expression   // single-assignment; reassigning is an error
assignment   := lvalue ("=" | "+=") expression   // "+=" is sugar for `x = x + expr`
property     := identifier ":" expression                        // declaration-body properties are newline-separated, not comma-separated
call         := expression "(" [argument {"," argument}] ")"
array        := "[" [expression {"," expression}] "]"
object       := "{" [key ":" expression {","? key ":" expression}] "}"
parameters   := parameter {"," parameter}
parameter    := identifier [":" type] ["=" expression]   // default: used when a caller omits the argument
lambda       := "(" [parameters] ")" "->" (expression | block)
if-expr      := "if" "(" expression ")" expression "else" expression
match-expr   := "match" expression "{" {(pattern | "_") "->" expression} "}"   // pattern: Enum.Variant or a bool/number/string literal
optional     := expression "?." identifier      // null / non-object / missing-field safe
optional     := expression "?." "[" expression "]"  // same, with a dynamic key
coalesce     := expression "??" expression      // left unless it is null

MATCH

match
 is a multi-way branch in expression position. Arms are tried top to bottom; the first whose pattern is deep-equal to the subject (the same comparison

var tier = match http_status {
    200 -> "ok"
    404 -> "missing"
    _   -> "error"
}

DETERMINISTIC SELECTION EXAMPLE

var passed_ids = [10]
var features = [
    {id: 20, status: "pending", priority: 2, depends_on: [10]},
    {id: 30, status: "pending", priority: 1, depends_on: [99]},
    {id: 40, status: "pending", priority: 3, depends_on: []}
]

var ready = features
    .filter((f) -> f.status == "pending")
    .filter((f) -> f.depends_on
        .filter((d) -> !passed_ids.contains(d))
        .is_empty())
    .sort_by((f) -> f.priority)

var next = ready.find((f) -> f.id == 20)

04
Control flow

Executable

Statements perform actions inside a 
step
, a 
tool
 method, a block lambda, or a test case.

Construct

Syntax

Effect

Variable

var x = expression

Creates a local binding.

Constant

const x = expression

Single-assignment binding. Reassigning it (
x = …
 / 
x += …
) is an error at 
mhl run
 and 
mhl lint
. Re-running the declaration itself — a 
const
 in a loop body — just rebinds. Also valid at pipeline top level.

Assignment

x = expression

Updates a variable, field, or index.

Add-assign

x += expression

Sugar for 
x = x + expression
 — same operand rules as 
+
 (numbers, strings, or arrays). Handy for accumulating into a list: 
errors += ["..."]
.

Condition

if (cond) { ... } else { ... }

Executes a block by condition.

Repetition

while (cond) { ... }

Repeats while the condition is true.

Iteration

for (var item in items) { ... }

Iterates over an array.

Error handling

try { ... } catch (err) { ... } finally { ... }

Handles recoverable failures.

Return

return value

Exits a method or step.

Transition

goto StepName

Jumps to another step, forward or backward. Only inside a 
workflow
 (not a plain 
pipeline
); the target must be a step of that 
workflow
.

Stop

break "reason"

Ends the current pipeline or loop early — a clean stop (exit 0, not a failure) that keeps the run's variable state as its result.

Pause

pause("reason")

Suspends the run at this step for a human-in-the-loop hand-off — not a failure, not a completion. Keeps the checkpoint; 
mhl run --resume
 / 
run/resume {runId, arguments}
 re-enters this step with the merged decision.

tool Summary {
    count_valid(items: {valid: bool}[]): number -> {
        var count = 0
        for (var item in items) {
            if (item.valid) count = count + 1
        }
        return count
    }
}

pipeline SafeRead {
    step Read {
        try {
            var config = json.parse(fs.read("config.json"))
            log.info("mode:", config.mode)
        } catch (err) {
            log.warn("invalid configuration:", err)
        } finally {
            log.info("read completed")
        }
    }
}

ERRORS

fail("message")
 creates a failure that 
catch
 can handle. Without a handler, the failure stops execution and the CLI returns a nonzero status.

05

agent

Executable

Declares an AI backend callable through 
.run(prompt: ...)
. The runtime supports local CLI processes and models served by Ollama.

CLI AGENT

agent Claude {
    engine: "cli/claude-code"
    command: "claude"
    args: [
        "-p", "${prompt}",
        "--output-format", "json",
        "--json-schema", "${schema}"
    ]
    retry: {
        max_attempts: 3
        delay: 2s
        retry_on: [500, 503, "timeout", "rate_limit"]
    }
    cache: { ttl: 10m, storage: "disk" }
    rate_limit: { requests_per_minute: 20, concurrency: 2 }
}

OLLAMA AGENT AND CALL

agent LocalCoder {
    engine: "ollama/qwen2.5-coder"
    endpoint: "http://localhost:11434"
    temperature: 0.1
    fallback: [
        agent {
            command: "echo"
            args: ["fallback: ${prompt}"]
        }
    ]
}

var schema = """
{"type":"object","properties":{"summary":{"type":"string"}}}
"""
var raw = LocalCoder.run(
    prompt: "Summarize the change.",
    schema: schema
)
var result = json.parse(raw)

ALPHA

RETRY

The exponential backoff carries 
full jitter
 (each wait is a uniform pick in 
[0, delay·2ⁿ]
) and is capped at 30s per wait — the cap applies from the very first wait, so a 
delay
 larger than it is trimmed immediately rather than sleeping once at the full amount — so a large 
max_attempts
 never grows an unbounded sleep. The wait is governed by the run's context: a run-level cancel, a 
timeout
 clause, or a served 
run/cancel
 aborts a retry that is only sleeping, rather than blocking until the delay elapses. A cancelled or deadline-exceeded call is never retried, whatever 
retry_on
 says; the caller then sees the last real failure, not the cancellation.

!

Do not place secrets in 
args
.

Prefer environment variables resolved by the invoked process. To preserve spaces and special characters in prompts, keep 
"${prompt}"
 as one complete array element.

BEFORE / AFTER HOOKS

An agent is a single-shot CLI process — it cannot decide mid-generation to call a tool or an MCP server. 
before
/
after
 are how the pipeline does that calling on the agent's behalf: real values, fetched before the prompt exists, not a hope the model reads and acts on an instruction.

agent Reviewer {
    command: "claude"
    args: ["-p", "${prompt}"]

    before: () -> {
        return {
            issue: GitHub.call("get_issue", { number: 42 }),
            diff: execution.git_diff()
        }
    }
    after: () -> {
        log("review is ${result.size()} characters")
    }
}

var review = Reviewer.run(
    prompt: "Issue: ${issue}\nDiff: ${diff}\nWrite a review."
)

A hook body is an ordinary expression scope: it calls declared 
tool
/
extension
/
agent
 names, native ops (
http
, 
cmd
, …) and 
mem
 the same way a step does, and sees the calling step's variables. Both hooks take 
no parameters
 — a leftover 
(mcp, tools) ->
 is an error.

's returned object's fields become real 
"${...}"
 bindings available to that call's 
prompt:
/
schema:
 arguments.

after
 runs once, against whichever leg — the primary agent or a successful 
fallback
 — produced the final response, with it bound in the body as 
result
. A non-
null
 string return replaces that response; anything else (including no 
return
) passes it through unchanged.

REAL CALLS

before
/
after
 execute real calls through mhl itself — the model never has to cooperate, and there is no separate declarative tool-scope list on the agent. When an agent needs a tool or an extension, call it from 
before
 and pass the result in through the prompt.

06

router

Executable

Declares a decision layer over a set of already-declared 
agent
s and exposes one method, 
.delegate(prompt: ...)
, that picks which one should handle a given prompt and runs it — the same call shape as 
agent.run(...)
, with routing built in. The LLM decision call is optional: a router that declares only 
select
 is a purely deterministic router.

HYBRID DECISION

agent Billing {
    command: "claude" args: ["-p", "${prompt}"]
    description: "Handles invoices, billing questions, and refunds"
}
agent Support {
    command: "claude" args: ["-p", "${prompt}"]
    description: "Handles account access and technical issues"
}
agent Judge { engine: "cli/claude-code" command: "claude" args: ["-p", "${prompt}"] }

router Frontdesk {
    agents: [Billing, Support]

    // Tried first: a deterministic hook over the prompt text. A match
    // skips the LLM decision call entirely. nameof(Billing) — not the
    // string literal "Billing" — so a typo here is caught by mhl lint.
    select: (prompt) -> {
        if (prompt.contains("invoice")) { return nameof(Billing) }
        if (prompt.contains("refund")) { return nameof(Billing) }
        return null
    }

    // Used only when select is absent or returns nothing that names a
    // declared agent: Judge is an ordinary, independently declared agent
    // — nothing about its call configuration is duplicated on the
    // router — sent one "pick one of these agents" decision call built
    // from the prompt already passed to .delegate(...).
    decider: Judge
}

var reply = Frontdesk.delegate(prompt: "My invoice is wrong.")

PURELY DETERMINISTIC — NO LLM CALL AT ALL

router Frontdesk {
    agents: [Billing, Support]

    // No decider declared at all: there is no decision call to cascade
    // to, so select alone must be exhaustive.
    select: (prompt) -> {
        if (prompt.contains("invoice")) { return nameof(Billing) }
        return nameof(Support)
    }
}

DESCRIPTION

The decision prompt sent to

DELEGATE

.delegate(prompt: ..., schema?: ...)
 resolves the agent to run — via 
select

/

OPTIONAL LLM CASCADE

The decision call is opt-in, not implied by declaring a router: it only exists when 
decider
 is declared. A router with neither a 
decider
 nor a

 hook is rejected by

 — it could never resolve an agent. A router with only 
select
 is accepted; if that hook ever misses at run time (with no decider to fall back to), 
.delegate()
 fails with a clear "no decider is configured" error instead of silently trying to run one.

NAMEOF

nameof(Name)
 returns a declared top-level name (agent, router, memory, tool, prompt, pipeline/workflow, extension, type, enum) as a string, validated to exist — the argument must be a bare identifier, not a string or an expression. Returning 
nameof(Billing)
 from 
select
 instead of the string literal 
"Billing"
 means a typo is a 
mhl lint
 error, and "go to definition" on 
Billing
 in an editor follows it to the real 
agent
 declaration. A non-null 
select
 return that still names no declared agent — a plain string typo, or a stale rename — always fails 
.delegate()
 immediately, listing the real agent names; it is never silently treated as "select declined to decide".

ALPHA

An 
agents:
 entry naming an undeclared agent, or a decision call whose answer matches none of them, is also an error — at 
mhl lint
 time for the former, at 
.delegate()
 call time for the latter.

07

prompt

Executable

A named template with parameters. A prompt renders to a string and can be passed to an agent or composed into another prompt.

INLINE AND COMPOSED

prompt Role() {
    "You are a software security reviewer."
}

prompt Review(role: prompt, file: string, code: string) {
    """
    ${role}

    Review ${file}. Return concrete risks and a minimal fix.

    ${code}
    """
}

var request = Review(
    role: Role(),
    file: "auth.go",
    code: fs.read("auth.go")
)

MARKDOWN BODY

review.prompt.md

# Review of ${file}

## Criteria
- correctness
- security
- compatibility

## Code
${code}

prompts.mh

prompt Review(
    file: string,
    code: string
) from "review.prompt.md"

var rendered = Review(
    file: "main.go",
    code: fs.read("main.go")
)

Prompt arguments are named: 
Review(file: "x", code: source)
.

Missing, extra, or unknown placeholders fail instead of producing incomplete text.

A parameter may declare a default — 
prompt Review(file: string, lang: string = "en")
 — used when the caller omits that named argument. Because prompt binding is by name, defaulted parameters may appear in any position, and a default expression is evaluated in the caller's scope (it cannot reference a sibling parameter).

Use 
\${NAME}
 in external Markdown when a placeholder must remain literal.

workflow Release {
    input environment: string
    var approved = false

    // No `checkpoint` block needed — per-step checkpointing is on by
    // default, so `--resume` already works. Add one only to tune it:
    //   checkpoint: { ttl: 30d }        // keep abandoned state longer
    //   checkpoint: { enabled: false }  // opt out entirely

    step Validate {
        var result = cmd.exec(["go", "test", "./..."], timeout: 2m)
        if (result.exit_code != 0) fail(result.stderr)
        approved = true
    }

    step Publish {
        if (!approved) goto Validate       // backward jump — needs `workflow`
        log.info("publishing to", environment)
    }
}

CHECKPOINT

The

 block is 
optional
. Every

/

 is projected with

 unless it says otherwise, so an interrupted run is always resumable with

 and a completed run clears its own state. Declare the block only to override a field —

 keeps the default strategy and just changes retention;

 turns checkpointing off for a workflow whose steps aren't safe to half-replay. 
strategy
 has one value today (
"per_step"
) and 
storage

"file"
).

SESSIONS

Every run gets its own directory 
.mhl/state/<session-id>/
, so two concurrent runs of the same pipeline never clobber each other's checkpoint. Each run prints a 
session: <id>
 line; a bare 
--resume
 follows the most recent one (via a 
.mhl/state/<pipeline>.latest
 pointer), and 
--session <id>
 pins an exact one. Abandoned session directories past their TTL are swept automatically at the start of a later run.

DEFINITION BINDING

Every checkpoint records a digest of the pipeline it was written for — that pipeline's own body plus the shared declarations it can reference (agents, tools, prompts, memory, extensions, types, imports); comments and formatting are excluded, and editing a 
sibling
 pipeline or a 
test
 block in the same file does not affect it. A 
--resume
 whose current digest differs is 
refused
 with a definition-mismatch error rather than splicing the saved variable state into changed control flow: restore the original definition, re-run without 
--resume
, or — if you know the edit is safe to resume through — pass 
--resume --force
 to downgrade the check to a warning. A checkpoint written by an older mhl that predates this field still resumes.

WHAT PERSISTS

Checkpoint state is JSON. A pipeline-scoped 
var
 survives 
--resume
 only if it holds a string, number, bool, 
null
, or an array/object of those; a resolved secret is stored as its re-resolvable reference (
env("…")
) and re-read on resume. Assigning something JSON cannot represent — a closure, a handle — to a pipeline-scoped 
var
 fails the run at the next checkpoint with a clear message rather than being silently dropped to 
{}
; keep closures in step-local 
var
s (which never cross a checkpoint), or set 
checkpoint: { enabled: false }
.

CREDENTIAL REFERENCES

Explicit credential resolution protects the exact nonempty value, including short or numeric strings and significant whitespace. Ordinary 
env()
 reads still use name/value heuristics; they do not declare every environment value a credential. Whole secret values with one known reference can be rehydrated; embedded or reference-free secrets are masked. If distinct references resolve to identical content in the same runtime process, string state cannot distinguish their origin: checkpoints retain an ambiguity marker and resume fails explicitly. Start a new run with distinct credentials instead of selecting either reference silently. Registration is process-wide, so an explicitly registered short value also masks matching text elsewhere in that process.

SIDE EFFECTS

A checkpoint records progress 
between
 steps, not the external effects a step performed. If a step creates a ticket, POSTs to an API, or runs a 
cmd
, then fails — or the process dies — before its checkpoint is written, 
--resume
 re-runs that whole step and 
repeats the effect
; a 
pause
 re-enters its step the same way, and a failed 
parallel
 branch re-runs alongside its already-completed siblings. mhl gives 
at-least-once
 execution per step, never exactly-once for an external system. Make a step that mutates the outside world idempotent: pass your own idempotency key to the API, check-then-act, or split prepare / approve / apply into separate steps so only the final, cheap apply can repeat. Give a repeated agent call a 
cache
.

CONCURRENT SUB-AGENTS IN A STEP

pipeline Review {
    input diff: string
    input changed_files: string[]

    spawn: { max_concurrency: 4 }   // run-wide ceiling; default 4

    step Analyze {
        spawn rev   = Reviewer.run(prompt: "review:\n${diff}")
        spawn tests = Tester.run(prompt: "run the tests for:\n${diff}")
        spawn sec   = Security.run(prompt: "security pass:\n${diff}")

        wait rev, tests, sec timeout: 90s        // wait-all, fail-fast
        // wait any rev, tests, sec              // first success, cancels the rest
        // wait 2 of rev, tests, sec             // first N successes (quorum)
        // wait rev, tests on_error: "collect"   // never fails the step; read .ok / .error

        log(rev.result)
        if (!tests.ok) log("tests failed: ${tests.error}")
    }

    step FanOut {
        // one spawn per element: `item` is bound while each call's arguments
        // are built, so every prompt differs. `reviews` is an array of task
        // handles — `wait` joins it as a group; it indexes and iterates.
        spawn reviews = Reviewer.run(prompt: "review file ${item}") for item in changed_files
        wait reviews timeout: 90s                // or `wait any reviews` / `wait 2 of reviews`
        for (var r in reviews) log("${r.status}: ${r.result}")
    }
}

For loops, always prefer an observable

TIMEOUT

A 
step <Name> timeout <duration> { … }
 clause caps how long that step may run — 
step Build timeout 3m { … }
. The runtime wraps the step's context with that deadline, so every blocking call it makes (an agent, 
http
, 
cmd
, an extension) is aborted when it elapses; the step then fails exactly as an explicit 
fail()
 would, so 
--resume
 / 
run/resume
 can still re-enter the step (unless the workflow set 
checkpoint: { enabled: false }
) — with a 
fresh
 budget (the duration is per attempt, never persisted). The same clause on a 
parallel <Name> timeout <duration> { … }
 group bounds the whole barrier and cancels every still-running branch; a branch may also carry its own 
timeout
, and the earliest deadline wins. A purely non-blocking runaway (a spinning 
while
) is still bounded by 
max_iterations
 / the interpreter's loop cap, not by this.

SPAWN

spawn
/
wait
 are step-scoped: any handle not joined by a 
wait
 is joined automatically when the step ends, so nothing runs across a checkpoint. If the process dies mid-step, 
--resume
 re-runs the whole step and re-issues every 
spawn
 — keep them idempotent (or give the agent a 
cache
). A spawned agent cannot itself 
spawn
, and an agent's 
log:
 file is ignored under 
spawn
 (its output goes to the step log instead). The fan-out form 
spawn xs = Agent.run(...) for item in <array>
 starts one background call per element with 
item
 bound while that call's arguments are evaluated, and binds 
xs
 to an array of handles in element order — index it (
xs[0].result
), iterate it (
for (var h in xs) …
), take its 
.size()
, and 
wait xs
 / 
wait any xs
 / 
wait N of xs
. A non-array iterable is a runtime error; an empty array binds an empty handle array that a plain 
wait
 no-ops on. The run-wide 
max_concurrency
 still bounds how many are in flight, so fanning out over a large collection is safe.

PARALLEL

A 
parallel <Name> { … }
 group runs its steps concurrently and joins them all before the pipeline advances — the step-level counterpart of 
spawn
 (which parallelises agent calls 
within
 one step). Each branch gets its own copy of the pipeline vars; on join, the writes are merged back, and a var two branches set to 
different
 values fails the run — so the outcome is deterministic. Branch output is buffered and printed in declared order. The group is atomic for checkpointing: a crash re-runs the whole group on 
--resume
, so branch steps must stay idempotent. 
goto
 may not target a grouped step or be used from within one, and 
break
 may not be used from within one.

    slug(text: string): string ->
        text.trim().to_lower().replace(" ", "_")

test normalize_examples {
    describe basic_slug {
        are_equal(Normalize.slug(" Feature Title "), "feature_title")
    }

    describe array_selection {
        var values = [1, 2, 3, 4]
        var even = values.filter((n) -> n % 2 == 0)
        are_equal(even, [2, 4])
        is_true(even.contains(4))
        is_false(even.contains(3))
    }

    describe future_behavior {
        incomplete("waiting for implementation")
    }
}
