# MELHORIAS

1. **WIKI como html estático com navegação e busca local (sem backend)**: O Senpai gera a WIKI em arquivos Markdown, devemos gerar a WIKI em HTML estático, com navegação e busca local (sem backend). 
2. **Remover elemento gráfico de seta do carde de brief**: Hoje no card de brief existe um elemento gráfico de seta apontando para cima que não é necessário, devemos removê-lo. Ele é apenas um elemento gráfico que não agrega valor à interface e pode ser confuso para o usuário.
3. **Alterar o botão "Aprovar" de lugar**: O botão "Aprovar" no card de brief está localizado em um lugar que não é intuitivo para o usuário. Devemos alterar a posição do botão para a barra superior da janela de preview do artefato, onde ele será mais visível e fácil de acessar.
4. **Persistir o log de prompt/resposta de cada chamada de LLM**: Hoje só o consumo (tokens/custo) de cada chamada ao `Writer.generate` é gravado em disco, em `projects/<project_id>/usage.jsonl` (via `Usage.append`, em `workflows/shared/agents/usage.mh`). O prompt enviado e a resposta bruta do agente (claude/codex/devin) não são persistidos em lugar nenhum — passam por stdin/stdout do CLI e só existem em memória durante a execução do step. Devemos gravar esse conteúdo (prompt final + resposta) por artefato/execução, no mesmo espírito do `Usage.append`, para permitir auditoria e depuração posterior de uma geração específica.
5. **Persistir os logs de execução de um run (hoje só em memória)**: O "logs view" do frontend (`app/frontend/src/views/logs-view.js`) mostra o progresso de um run consultando a tool `mhl_run_logs` via `mhl serve mcp`, mas esse histórico é mantido apenas em memória pelo processo `mhl` — ao fechar o app ou matar o processo, o log some. Devemos gravar esses logs de step em disco (ex.: por `project_id`/execução) para que fiquem disponíveis depois que o processo termina, em vez de servirem só como debug do run corrente.
6. **melhorar a experiência de lista de logs**: Hoje a lista de logs é apenas uma lista de linhas de texto, sem contexto. Devemos melhorar a experiência de visualização da lista de logs, agrupando por step, mostrando o status (sucesso/erro) e permitindo expandir cada step para ver os logs detalhados.
7. **Melhorar a lista de agentes**: Hoje a lista de agentes é apenas uma lista de linhas de texto, sem contexto. Devemos melhorar a experiência de visualização da lista de agentes, mostrando o status (ativo/inativo), permitindo expandir cada agente para ver os detalhes e logs, e adicionando filtros para facilitar a busca por agentes específicos.
8. **Melhorar a lista de modelos**: Hoje a lista de modelos é apenas uma lista de linhas de texto, sem contexto. Devemos melhorar a experiência de visualização da lista de modelos, mostrando o status (ativo/inativo), permitindo expandir cada modelo para ver os detalhes, e adicionando filtros para facilitar a busca por modelos específicos.
